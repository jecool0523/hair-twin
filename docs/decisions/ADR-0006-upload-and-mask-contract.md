# ADR-0006: Image transport and mask contract

Date: 2026-07-16
Status: Accepted and verified locally

## Decision

Capture uses `multipart/form-data` with image bytes and a region-map binary.
Base64 JSON is rejected. The server probes the real PNG/JPEG/WebP signature and
dimensions, enforces limits, and does not trust client MIME or dimensions.

The server derives the complete mask set from the region map. Every mask and
the region map are private, expiring objects. Jobs bind to one immutable mask
contract id. Retry derives a new attempt-specific contract with tighter tuning;
prior contracts remain auditable and cannot be reused for the wrong attempt.

Stored masks use a byte-per-cell grid where `1` means editable. Storage encodes
the grid as a lossless RGBA PNG at segmentation resolution. The Python worker
decodes it, validates binary values, resizes with nearest-neighbor sampling to
the exact source dimensions, and emits an RGBA PNG where transparent pixels are
editable for the OpenAI Images API. Tests assert dimensions, polarity, binary
edges, and malformed-mask rejection.

Decoded grid payloads, source dimensions, provider responses, and candidate
counts are bounded before allocation. Worker object paths must be canonical and
match the database-claimed salon and session. Customer-media Storage objects
are immutable: replacement policies are removed, so a new object name and row
are required instead of overwriting existing source, mask, or generated bytes.

Generation jobs may use global styles or styles owned by the same salon only.
Database triggers reject cross-salon private styles and prevent an in-use
global style from being rebound to a different tenant.

## Trust boundary

Segmentation currently runs in the browser, so a hostile client could doctor a
region map. The client still cannot assert coverage, cross tenant/session
boundaries, reuse expired contracts, or choose provider-ready bytes. Moving
segmentation to a reviewed worker model is the long-term trust-boundary change.

## Privacy boundary

Masks are treated as sensitively as source photos and deleted by the same
retention workflow. The OpenAI adapter is implemented but sends data only when
both explicit external-AI and overseas-transfer gates are enabled. Provider
legal approval and production CV scoring remain launch gates.
